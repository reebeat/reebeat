# @reebeat/cache-fs

`AssetCache` on a directory. `fsAssetCache(dir)` is a `Layer` over `FileSystem`, `Path` and `Digest`. The key is `assetKey` of `@reebeat/services`. An asset is `<dir>/<key>.<name>` for each file and `<dir>/<key>.provenance.json` **last**, so a reader that finds the provenance finds every file: a put removes an old provenance first, writes the files, then renames the new provenance into place. The provenance file holds the provenance and the size and SHA-256 of each file; a read verifies each, so a truncated or swapped file is `CacheFailed`. A key or file name that is not a plain file name is refused (`CacheFailed`), and a secret-looking setting is `SecretLikeSetting`.

`bun run test` (offline, in `ready`): the `AssetCache` contract, with stores whose file system fails at each step of a put (the provenance renamed, the second and the first file written, the provenance written) for the atomicity clause, plus the layout, the tamper check, the refused names and the replace-whole behaviour.

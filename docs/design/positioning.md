# How reebeat differs from existing tools

Status: design note. Date: 2026-10-29. Spec: [0011](../specs/0011-positioning.md). Decided by: the operator, 2026-10-29 (the words in the README opening, the categories below and the rules of the comparison).

This note compares the approach of reebeat with the tools that people use today to make video, decks and animation. It tries to be fair. It credits what each tool does better than reebeat, and it cites the official documentation of each tool for every claim about how the tool works.

## Rules of this note

- **Sourced.** Each claim about another tool links to the official documentation of that tool. The links are read on 2026-10-29. Documentation changes, so a claim is only as new as that date.
- **"Not found" is not "absent".** For some tools and topics the pages that were read say nothing. The table then says "not found". This means that the pages read give no statement. It does not mean that the tool lacks the feature.
- **No performance claim without a measurement.** Where this note describes speed, it quotes what the documentation says, or it says "not measured". reebeat has one measurement of its own, given in "Performance" below. No tool was benchmarked against another.
- **Status first.** reebeat is young. Each statement about reebeat says whether the code does it today, is building it, or only plans it. The README has the same status table.
- **Words.** *Creating* is the creative work of the author. *Build* is what reebeat does with the result ([GLOSSARY](../../GLOSSARY.md), "Words for the work").

## What reebeat is, in one picture

```text
creating                                   building (reebeat)
────────                                   ──────────────────
 you declare:                               reebeat generates:
  scenes (states), their elements,           the Plan (for review)
  the narration, when things happen          the motion between scenes
  (anchors), the story's structure           ┌─ Video   (frames on a controlled clock)
              │                              ├─ Deck    (reveal.js, speaker notes)
              ▼                              ├─ subtitles, chapters
        one Fountain file  ───────────────▶  └─ more artifacts later
                                            same inputs → same bytes (F6)
```

You declare the narrative and its structure. reebeat decides the frames.

How the build works, and which mechanism delivers which quality: [how-it-works.md](how-it-works.md).

## Prior art for the identity diff

reebeat takes its motion from matching the same element in two states. Three tools did this before.

- **Keynote Magic Move.** Objects that appear on both slides move to their new place. Objects on only one slide fade out or in. The docs describe no id or name for an object ([Keynote](https://support.apple.com/guide/keynote/add-transitions-tanff5ae749e/mac)).
- **PowerPoint Morph.** Morph matches objects on its own. The author can force a match by giving two objects the same name that starts with `!!` ([PowerPoint tips](https://support.microsoft.com/en-us/powerpoint/morph-transition-tips-and-tricks)). The training page says that Morph "can do similar things" as Magic Move ([Morph](https://support.microsoft.com/en-us/powerpoint/training/use-the-morph-transition-in-powerpoint)).
- **reveal.js Auto-Animate.** Two adjacent slides opt in. A `data-id` gives an element an explicit identity, and it wins over automatic matching. Unmatched elements fade in by default ([reveal.js](https://revealjs.com/auto-animate/)).

reebeat uses the same idea with explicit ids (`{id=one}`) in a plain-text source, and today it uses reveal.js Auto-Animate to draw the motion ([GLOSSARY](../../GLOSSARY.md), "Identity diff"). reebeat builds a reviewable Plan from the match, anchors other effects to the lifecycle of a matched element, and checks the written files. None of the pages read for the tools compared here describes such a step. That is a statement about the pages read, not proof that no tool does it. No wider search was made.

Remotion shares a second idea: a video frame is a function of the frame number ([Remotion](https://www.remotion.dev/docs/flickering)). reebeat's Video is built the same way ([AGENTS.md](../../AGENTS.md)).

## Performance

Qualitative, from the documentation, plus one measurement of reebeat. Nothing here compares two tools.

- **Real-time editors** state real-time or GPU-accelerated playback: [Resolve](https://www.blackmagicdesign.com/products/davinciresolve/fusion), [Premiere](https://helpx.adobe.com/premiere/desktop/get-started/download-and-install/mercury-playback-engine-gpu-accelerated-in-premiere.html), [Final Cut Pro](https://support.apple.com/guide/final-cut-pro/intro-to-the-magnetic-timeline-verb8fcfc133/mac). The doc pages give no render times.
- **Code-driven renderers** render many frames in parallel because each frame is independent. Remotion says that deterministic videos allow distributed renders with Remotion Lambda, "which can render a video much faster than real-time" ([Remotion](https://www.remotion.dev/docs/flickering)). Manim reuses cached output for a `play` call whose hash is unchanged ([Manim](https://docs.manim.community/en/stable/guides/deep_dive.html)).
- **reebeat today** rebuilds everything. On one machine, one build of `stories/same-id` took 61.9 s and a second build took 60.2 s ([spec 0001, Revisions](../specs/0001-release-1-screenplay-to-deck-and-video.md), 2026-10-28). The story has changed since, and the figures were not measured again. They are not a benchmark. Speech is cached; render segments are not. Incremental builds are planned ([#9](https://github.com/reebeat/reebeat/issues/9)).
- **Not measured:** reebeat against any other tool, on any story.

## The experience of creating

**(a) Traditional video editors.** You open footage and a timeline. You place each clip, trim it, add a transition from a menu and adjust keyframes by eye. You see the result at once, in real time. The timeline is the source. A change of narration means moving every later clip by hand. With reebeat you do not place anything on a time axis. You declare the scene, say that an effect happens at a word, and read the Plan. The motion and the frame are generated. You lose the instant, direct control of the picture. You gain a source in which an edit to a sentence moves everything that is anchored to it.

**(b) Presentation and multimedia programs.** You work slide by slide. You drag objects, pick a transition from a menu and set a time for each slide. Magic Move and Morph already derive motion from two slides, and they are quick and friendly. The source is a binary document. Video is an export of the show, with the timings you set. With reebeat the slides are Scenes in a text file, narration is part of the source, and time comes from the words and the anchors. The Deck and the Video come from the same file, so they cannot disagree.

**(c) Motion-graphics automation tools.** You write code, expressions or a state machine. You get exact, rich animation and a large ecosystem. You decide the motion yourself, in a procedure (`self.play`, `yield*`, `interpolate`) or in a hand-made state machine. With reebeat you declare the states and their structure, and the motion between them is generated by identity diff. You give up bespoke animation. You gain a smaller source that says what the story is, not how each frame is drawn.

In all three cases the move is the same: from placing and procedure to **declaring the narrative and its structure**, and letting the build generate motion and artifacts.

## What each category does better than reebeat

- **Video editors:** real-time playback and scrubbing, footage, colour and audio post-production, mature editing, large ecosystems of plug-ins and templates ([Resolve](https://www.blackmagicdesign.com/products/davinciresolve), [Final Cut Pro](https://www.apple.com/final-cut-pro/)), and multi-user editing in the application ([Resolve](https://www.blackmagicdesign.com/products/davinciresolve/collaboration), [Premiere](https://helpx.adobe.com/premiere/desktop/collaborate-with-others/collaborate-using-team-projects/about-team-projects.html)).
- **Presentation programs:** speed for a single deck, a visual editor anyone can use, live presenting, and live co-editing ([PowerPoint](https://support.microsoft.com/en-us/powerpoint/work-together-on-powerpoint-presentations), [Keynote](https://support.apple.com/guide/keynote/intro-to-collaboration-tan4e89e275c/mac), [Canva](https://www.canva.com/help/collaborate-with-anyone), [Google Slides](https://support.google.com/docs/answer/190843?hl=en)). PowerPoint also has an Accessibility Checker and automatic alt text today ([PowerPoint](https://support.microsoft.com/en-us/accessibility/powerpoint/make-your-powerpoint-presentations-accessible-to-people-with-disabilities)).
- **Motion-graphics tools:** rich, hand-made animation; ecosystems (React for Remotion, the After Effects template market through MOGRT); interactive runtimes and state machines in Rive ([Rive](https://rive.app/docs/editor/state-machine/state-machine)); small, portable files in Lottie ([dotLottie](https://dotlottie.io/intro)); and live editors in Motion Canvas and Rive ([quickstart](https://motioncanvas.io/docs/quickstart)). Several already offer agent integrations: Remotion's skills and WebMCP, Rive's MCP server, Canva's MCP server, and the Premiere and After Effects AI assistants (links in the table).

## When not to use reebeat

Use another tool when any of these is true.

- You need **real-time, hands-on editing** of a timeline, or you need to scrub and see the result at once. reebeat builds, then you watch.
- Your material is **footage**: camera clips, colour grading, audio mixing. Use a video editor.
- You need **bespoke, hand-made animation**: characters, illustration, custom physics. Use After Effects, Rive, Remotion or Motion Canvas.
- You need **interactivity today**. The Deck is a reveal.js page that the viewer steps through, and the Video is a file. An interactive web artifact, driven by viewer events, is planned ([#19](https://github.com/reebeat/reebeat/issues/19)). Interactive lessons are a deferred investigation ([#20](https://github.com/reebeat/reebeat/issues/20)).
- You need **a visual, multi-user editor today**. reebeat has a command line and a text file. A multiplayer editor is a planned product, not a feature of this repository ([open-core boundary](open-core-boundary.md)).
- You need **a PowerPoint file, a Lottie file or another outside format** as the output. reebeat writes a reveal.js Deck and an MP4 today.
- You need **full accessibility outputs today** (sound descriptions in captions, audio description, reduced motion). Subtitles, speaker notes and chapters exist. The rest is planned ([#12](https://github.com/reebeat/reebeat/issues/12)).
- You make **one deck once**. The cost of declaring a story pays back when the story changes, or when you need the same story as a Deck and a Video.
- You cannot run the toolchain. The build needs Chromium, ffmpeg and whisper.cpp, provided by devenv on Linux ([README](../../README.md)).

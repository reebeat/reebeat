# 0004 Explicit state machines and timing combinators

Status: **plan** (frozen when its PR opens; revisions are dated entries at the end). Date: 2026-10-29. Decided by: the operator's direction of 2026-10-29: make temporal media declarative and explicit by **declaring the implicit state machines explicitly** (elements, effects, transitions, beat-to-beat state changes), with **SMIL 3.0 timing** for event semantics and **functional reactive animation** (Elliott and Hudak, ICFP 1997) for behaviours versus events.
Process: [spec 0000](0000-development-lifecycle.md). Builds on [spec 0002](0002-explicit-anchors-and-syntax.md) (anchors, effects block, offsets); stacked on PR #5 ([spec 0003](0003-effect-4-1-upgrade.md), Effect 4.1.0), which merged to `main` as `fc65387`, so this branch is based on `main`: `feat/0004-state-machines`.
Sources: SMIL 3.0 Timing and Synchronization (<https://www.w3.org/TR/SMIL3/smil-timing.html>), "Functional Reactive Animation" (<https://dl.acm.org/doi/10.1145/258948.258973>). RxJS marble notation explains the operators below; no RxJS runs anywhere.

## Problem

Spec 0002 made every anchor explicit, but the model under the anchors is still implicit, in four places:

1. **The lifecycle of an Element is in code, not on paper.** `eventKind` in `packages/core/src/events.ts` decides which of `enter`, `exit`, `move`, `update` happens, from the identity diff; `RendererLifecycle` says when. Which states an Element passes through (absent, entering, present, moving, updating, exiting) exists nowhere a reader can see.
2. **The anchor vocabulary is a hand-written list.** `anchorForms`, the `Anchor` union, `validate.ts`, `resolve.ts` and the verifier each list the five kinds again. A new moment needs five edits, and nothing says that `one.move.start` is an edge of a declared machine and `one.glide.start` is not.
3. **An effect has a hidden machine too.** A `focus` rings an Element until another `focus` starts or the slide changes (the `focused` variable of `deck.js`). Nobody can anchor to the end of that ring, or end it earlier. The slide change silently ends it; no document says so.
4. **There is no algebra.** An author cannot say "when both are done", "the earlier of", "at each of these words", "until the narrator says it", "not more often than every 250 ms". `N%` is a spelling, not a concept.

## Goal

- **One source of truth: the machines.** Every thing that has a lifecycle has a declared finite-state machine, written once as data in `packages/core/src/machines.ts`: the Element (three regions: presence, position, style), the effect, the Scene (the slide change) and the Beat. Its **edges** come from the identity diff between Keyframes (Elements), from the effect's own timing (effects) and from the Scene sequence (slide changes). The **anchor vocabulary is generated from the machines**: every transition yields `.start`, `.end` and a progress behaviour; every state yields enter and leave events. An anchor that names no edge of a declared machine is a lint error with `did you mean`. The grammar document, the parser, the linter and the `Anchor` schema derive from the declarations; nothing else lists an event.
- **Combinators with SMIL semantics.** `last`, `first`, `each`, `within`, effect durations (`until`), derived events (`let`), `throttle` and `stagger`, and `beat(n).start|end` as sources. Each is a total function from finite lists of frames to a list of frames, resolved at plan time. Cycles stay a lint error. `reebeat plan --timing` prints, for every effect and every derived event, the intent and the resolved frame or frames.
- **Behaviours versus events, minimal.** An Element's progress through a transition is a **behaviour** (a function of time, 0 to 1). `N%` of 0002 becomes the **threshold event** `when(one.move.progress >= 50%)`.
- **Falsifiers observe the video and the audio**, not the plan: every new kind of anchor and every combinator is observed in the written Video and mix, and a duration effect's end is observed too.

Non-goals: continuous bindings (volume follows speed, a colour follows progress) are **future work**; this spec has behaviours only as the thing a threshold event is taken from. More effect kinds. A visual editor. A new narrator, a new voice, a changed Line: the dialogue of `stories/same-id` is byte-identical, so the speech cache keeps hitting (see F7).

## The machines (declared in `packages/core/src/machines.ts`)

A **machine** is `{ id, subject, initial, states, transitions }`. A **transition** `{ name, from, during, to, progress }` is a timed edge: it starts when the machine leaves `from`, spends its window in `during`, and ends when it reaches `to`. `progress` says what the behaviour looks like: `time` (linear in time) or `eased` (the renderer's declared easing). A transition with no window (start equals end) is an **instant**. A machine is a plain value; `vocabulary(machine)` and the checks below are pure functions of it.

| Machine | Subject, how it is written | States (first is initial) | Transitions | Where the edges come from |
| --- | --- | --- | --- | --- |
| `presence` | an Element: `<id>` | `absent`, `entering`, `present`, `exiting` | `enter`: absent, entering, present (`time`); `exit`: present, exiting, absent (`time`) | identity diff: `enter` = only in this Scene, or a `show` effect for a `visible=false` Element; `exit` = only in the previous Scene. An Element that is in both Scenes starts `present` |
| `position` | an Element: `<id>` | `still`, `moving` | `move`: still, moving, still (`eased`) | identity diff: the cell changed |
| `style` | an Element: `<id>` | `steady`, `updating` | `update`: steady, updating, steady (`eased`) | identity diff: the class or the text changed |
| `effect` | an effect: `<id>` | `idle`, `active`, `done` | `run`: idle, active, done (`time`); **its name is not written** | the effect's own timing: it starts at its fire frame and ends at its window end (a `show`: the renderer's declared `showMs`; a `focus`: its `until` or the end of the Scene; a `sound`: no end is known, so `.end` is an error) |
| `slide` | the Scene: `scene` | `before`, `changing`, `shown` | `transition`: before, changing, shown (`time`) | the Scene sequence: a slide change is the transition between two Scenes (the incoming one, from the slide change frame for the renderer's declared window) |
| `dwell` | a State of the Scene: `state(<n>)`; its one state is the dwell itself and its name is not written | `dwell` | none | State 1 opens with the Scene; each Beat leads to the next State. It holds from the end of the Beat before it to the start of the Beat after it |
| `beat` | a Beat of the Scene: `beat(<n>)`; its transition is not named | `waiting`, `changing`, `done` | `change`: waiting, changing, done (`time`) | the engine generates a Beat from each distinct fire frame of a `show` or `focus` after the Scene's first frame; it lasts as long as the slowest step that fires then (a `show` fades for the declared time, a `focus` is an instant) |

The graph model (Revision 2026-10-29, "State, Beat, Scene"): a **State** (node) holds for a dwell interval; a **Beat** (edge) is the transition the engine generates from one State to the next, with `beat.start` the leave of the State before it and `beat.end` the enter of the State after it (`{state.leave = beat.start} --beat--> {beat.end = state.enter}`); a **Scene** is a compound State (Harel's superstate) that groups the States sharing one identity scope, and the `slide` machine is the Beat between two Scenes. An **effect's** machine is `idle` until its fire frame, `active` for its window, `done` after. Effects anchored to a Beat's events are Mealy outputs (on transitions); effects anchored to a State's enter or leave are Moore outputs (on states).

### What the declarations generate

For a machine with subject head `H` (`<id>`, `scene`, `beat(<n>)`):

| Source | Spelling | Meaning |
| --- | --- | --- |
| each transition `t` | `H.t.start`, `H.t.end`, `H.t.<N>%` | the first frame of the window, the frame it settles, and the sugar below |
| each transition `t` | `H.t.progress` (only inside `when(... >= N%)`) | the behaviour of the transition, 0 to 1 |
| each state `s` | `H.s.enter`, `H.s.leave` | the first frame the machine is in `s`, and the first frame it leaves it; no event when it never is |

A transition or a state whose name is **elided** in the declaration (`effect`'s `run`, `beats`' `beat`) is written without it: `r1.start`, `beat(2).start`. For `beats` the state events are spelled `start` and `end` (the declaration says so). The `slide` machine declares three **aliases**, the only hand-written spellings: `transition.<point>` is `scene.transition.<point>`, `scene.start` is `scene.before.leave` (the slide change frame) and `scene.end` is `scene.shown.leave` (the last frame of the Scene). `vocabulary(machines)` is the list of every spelling; the parser reads an anchor only through it, the linter reports a path that is not in it (`one.glide.start` names no transition of `presence`, `position` or `style`; nearest `one.move.start`), and `docs/grammar/effects.md` prints it. A test adds a transition to a copy of a machine and sees the vocabulary, the parser and the document follow.

An **occupancy** is a state's interval in the Scene: the initial state from the Scene's first frame to the first transition's start; a transition's `during` state for its window; the `to` state from the window's end to the next transition or the end of the Scene. `enter` is the start of the state's first interval, `leave` the end of it; the slide change leaves every state (Revision 2026-10-29, "leave"), so a state still held at the end of the Scene is left at the Scene's last frame.

## The event model

Time is an integer frame at `settings.fps`. An **event** is a finite, strictly increasing list of **occurrences**, each `{ frame, window }` (the window of the anchored thing, `start <= frame <= end`, an instant when equal). A **behaviour** is a function from a frame to 0..1 that a transition declares; the only thing built from it here is the threshold event `when(<transition>.progress >= N%)`: the first frame at which the behaviour reaches N percent (`eased`: by the renderer's declared easing, as in 0002; `time`: linear). The spelling `one.move.50%` of 0002 **stays as sugar**: it is read as `when(one.move.progress >= 50%)` and printed in that canonical form by `plan --timing` next to what was written. (Decision, recorded below: keeping the spelling costs nothing and keeps every story of 0002 valid.)

Each combinator is a total function; marble notation draws frames as columns (`-` is a frame, `|` the end of the Scene, a letter an occurrence). Input events here come from `word("a")`, `word("b")`, `word("c")` at frames 4, 8, 14 (`a` at 4, `b` at 8, `c` at 14).

| Combinator | SMIL / FRP semantics | Definition | Marble |
| --- | --- | --- | --- |
| `last(e1, ..., en)` | `endsync="last"`; `forkJoin`: it happens when every operand has happened (the draft called it `all`; SMIL's `endsync="all"` means something else, see Revisions) | `[max over i of last(ei)]`; empty if any operand is empty | `a-b---c` => `------c` |
| `first(e1, ..., en)` | `endsync="first"`; `race`: the earliest | `[min over i of first(ei)]` over the non-empty operands; empty if all are | `a-b---c` => `a` |
| `each(e1, ..., en)` | a begin-value list; `merge`: every occurrence | the union, sorted, equal frames once | `a-b---c` => `a-b---c` |
| `within(e, state(k))` | scoping by State (the dwell between two Beats) | the occurrences of `e` inside the interval of State `k` | `a-b---c` with State 2 = frames 6 to 12 => `--b` |
| `e +/- d` | an offset on a begin value | every occurrence shifted by `d` (`ms`, `s`, `f`, or `%` of its own window) | `a-b` +2f => `--a-b` |
| `let n = e` | `share`: one evaluation, many subscribers | the same list wherever `n` is used | |
| `each(...,  throttle=d)` | `throttle` (leading): drop an occurrence closer than `d` to the last kept one | keep the first; keep `f` when `f - lastKept >= d` | with a=4, b=8, c=14: throttle=5f => 4, 14 (8 is 4 after 4: dropped); throttle=4f => 4, 8, 14 |
| `each(..., stagger=d)` | delay so that two are never closer than `d` | `f1' = f1`, `fi' = max(fi, f(i-1)' + d)` | with a=4, b=8, c=14: stagger=6f => 4, 10, 16; stagger=3f => 4, 8, 14 |
| `until e` on an effect | SMIL end value; `takeUntil` | the end of an instance is the first occurrence of `e` after its start, else the end of the Scene | below |

An `each` is the only combinator whose result may have several occurrences; an effect with several occurrences has **one instance per occurrence** (SMIL's begin-value list), and only a `sound` may (a `show` and a `focus` happen once: `ManyFires`). Instances of one effect do **not** restart each other: this departs from SMIL's default `restart="always"` on purpose (two dings 300 ms apart are two dings; cutting the first would change the audio of every sound).

### Durations and the slide change

An effect with a window is `active` from its fire frame to its end:

- `show`: for the renderer's declared `showMs` (the fade), then it stays shown for the rest of the Scene.
- `focus`: until its `until` event, **or the end of the Scene**. `until` is the SMIL end value: the first occurrence of the event **after** the fire frame (equal or earlier occurrences are ignored); an event that never happens after it leaves the ring on to the end of the Scene.
- `sound`: no window; it plays to its natural end, which the plan does not know, so `until` and `.end` are errors on it. (Decision: a short one-shot is not cut by an event.)

**The slide change interrupts every running effect.** SMIL ends the children of a time container when the container ends; the Scene is that container. An `until` later than the Scene's last frame, or none, ends the effect at the Scene's last frame (`interrupted`, printed by `plan --timing`), and the Deck and the Video drop the ring with the slide as they always did. **A later `focus` also ends the ring** of an earlier one (the renderer has one ring: `focused` in `deck.js`; its machine is now declared, the rule is a rendering rule, not an event). Where a `focus` ends before the Scene does by its own `until`, the Deck gets an **end step** (a fragment that removes the ring) and the Video a command at the end; both are in the Timeline (`endFrame`, `endCommandFrame`) and in `stepsOf`, the one definition the Deck, the capture and the verifier read.

## Grammar

```text
block    ::= "[[effects" NEWLINE { line NEWLINE } "]]"
line     ::= effect | let
let      ::= "let" name "=" event                                   a derived event, local to the Scene
effect   ::= id ":" verb arg "at" when [ "until" end ]
when     ::= event | number "s" "because" quoted                    absolute only with a reason
end      ::= event                                                  the SMIL end value, `focus` only
event    ::= term [ offset ]
term     ::= anchor | name
           | "last(" event { "," event } ")" | "first(" event { "," event } ")"
           | "each(" event { "," event } [ "," "throttle=" duration ] [ "," "stagger=" duration ] ")"
           | "within(" event "," "state(" n ")" ")"
           | "when(" path ".progress" ">=" N "%" ")"                     path: `<id>.<transition>`, `beat(n)`, `scene.transition`
anchor   ::= "word(" quoted [ "," n ] ")" "." edge                   a word of the narration (a source, not a machine)
           | the vocabulary generated from the machines            see "What the declarations generate"
offset   ::= ( "+" | "-" ) number ( "ms" | "s" | "f" | "%" )
duration ::= number ( "ms" | "s" | "f" )
```

`grammar.ts` derives its productions from the machines and `docs/grammar/effects.md` is generated from it (as in 0002, F3); every example of the document is a whole story that the parser reads.

## Plan contract (the authority is `packages/core/src/plan.ts`)

- `Anchor` becomes three kinds, generated from the machines: `word` (as before), `edge` (`{ subject, transition, at }` with `at` a `Point`: `start`, `end`, or `{ percent }`) and `state` (`{ subject, state, event: "enter" | "leave" }`), where `subject` is `{ kind: "element", id }`, `{ kind: "effect", id }`, `{ kind: "scene" }` or `{ kind: "beat", n }`. The five hand-listed kinds of 0002 are gone.
- `EventExpr` is `anchor`, `ref` (a `let` name), `last`, `first`, `each` (with optional `throttle` and `stagger`), `within`, or `shift` (an offset). `Effect.when` is `{ event: EventExpr }` or `{ absoluteFlicks, reason }`, and an effect may carry `until: { event }`; no text is stored next to an expression (Revision "the IR stores no derived fact"). A Scene has `events`: its `let` lines.
- The Timeline's `TimedEffect` is one **instance**: `instance` (1-based), `fireFrame`, `commandFrame`, `intent`, and for an effect with a window `endFrame`, and for a `focus` that ends by its own `until` before the Scene does, `endCommandFrame`. `TimedScene.events` lists each `let` with its frames.

## Decisions recorded at the start (operator-owned forks are listed in the PR)

1. **`N%` stays as sugar** for `when(... progress >= N%)`; `plan --timing` prints both.
2. **Durations are for `focus` only.** A `show` is permanent and a `sound` plays out; `until` on them is an error that says so. `for <duration>` (an end relative to its own start) is future work: it needs a self-reference rule.
3. **Beats are the steps of a Scene** (glossary: "the step one `show` or `focus` effect causes"); `beat(n)` is scoped to its Scene, and `within(e, beat(n))` is the scoping combinator. A step cannot be timed by a Beat it opens (cycle error); a `sound` can.
4. **`throttle` and `stagger` are options of `each`** (the group is the list of events), not of an effect.
5. **Instances do not restart each other** (a departure from SMIL's default `restart`).
6. **Words are a source, not a machine.** The aligned words are data; a Line machine (`idle`, `speaking`, `done`) is future work together with continuous bindings.

## Future work (recorded, not built)

Continuous bindings (`volume = f(speed)`, a behaviour on the right of a binding); `for <duration>`; `restart` as a declared choice; a Line machine; effects with several targets (`stagger` over a group of Elements); durations for `sound` (loops, fades).

## Revisions

- **2026-10-29, plan written** against 0002 as merged (`a05f49b`) and PR #5's head (`b20c2ba`), before any code.
- **2026-10-29, rebased on `main`.** PR #5 merged as `fc65387`; the tree of its head `b20c2ba` equals `main`'s, so the branch was rebased with no conflict and the PR is based on `main`, not on `chore/effect-4.1`.
- **2026-10-29, State, Beat, Scene (the operator's reframing; terms confirmed by the operator).** reebeat is a reactive, declarative motion-graphics compiler: authors declare **States** (nodes) and the engine generates the **Beats** (edges) and the events they produce; effects subscribe to those events. A State holds for a dwell interval; a Beat leads from one State to the next (`beat.start` = the previous State's leave, `beat.end` = the next State's enter); a **Scene** is a compound State (Harel 1987 *depth*, a superstate) that groups the States sharing one identity scope, and the Beat between two Scenes is an edge between compound States (the `slide` machine; its spellings `transition.*`, `scene.start`, `scene.end` stay). **Orthogonality** (Harel): each Element's three machines and each effect run as parallel regions inside a Scene. **Broadcast events**: effects subscribe to events the engine generates. Effects on a Beat's events are **Mealy** outputs, effects on a State's enter or leave are **Moore** outputs. As built: the machine `beats` of the plan became `dwell` (subject `state(n)`, events `enter` and `leave`) and `beat` (subject `beat(n)`, transition `change`, so `beat(n).start|end|N%|progress`); `within(e, beat(n))` became `within(e, state(n))`; the anchor kind `state` of the Plan contract became `occupancy` (the subject kind `state` is the Scene's State). Keyframe stays the visual part of a State (GLOSSARY). Element-level property transitions (`color`, `position`, `size`, `transition: position 400ms ease-out`) and media-query variants are spec 0005 and future work, not built here.
- **2026-10-29, "leave" is total.** The slide change at the end of the Scene leaves every state, so the end of a state's last interval is the Scene's last frame (SMIL: the parent ends its children); `scene.end` is `scene.shown.leave`. This replaces "the first one that ends before the Scene does" of the Event model and removes the "never happens" case for a state the Scene reaches. A state a Scene never reaches is an error (`NoSuchEvent`, `UnresolvedAnchor`).
- **2026-10-29, the IR, and three kinds of format.** The canonical IR is the declared graph: `GraphSchema` in `packages/core/src/graph.ts`, an Effect Schema, closed (an excess key is a decode error) and versioned (`version`, `graphVersion` = 1); JSON is its canonical encoding (`jsonCodec`). The Plan is a function of the IR (`planOf(graph, sourceSha256, rate)`: identity diff, settings; `schedule` adds the Timeline). Three kinds of format, different interfaces so that no artifact has a decode: an **IR codec** (`IrCodec`: encode and decode, the law `decode(encode(ir)) = ir` tested; JSON is the canonical one), an **importer** (`Importer`: foreign format to the IR, one way, lossy, its output reviewed; the Fountain reader is `fountainImporter`) and an **artifact renderer** (`ArtifactRenderer`: output only: Video, Deck, VTT, Fountain, a Mermaid diagram). `stories/same-id/story.fountain` stays the input; switching the committed source to IR JSON and the Fountain renderer are spec 0006. XState JSON and SCXML codecs are 0006 as well.
- **2026-10-29, exact time; the frame rate is a render setting.** IR time is exact and independent of the frame rate: a whole number of **flicks** (1/705,600,000 s), chosen because it divides evenly into one frame of 24, 25, 30, 48, 50, 60 and 120 fps, so `+0.1s` is 70,560,000 flicks, never a float and never a frame (integer milliseconds could not hold `0.0005s`; a rational needs a second field for no gain). Offsets and durations in the IR are `flicks` or `f` (output frames at the Plan's declared rate: the spec says so; a frame appears only in the Timeline); an absolute time is `absoluteFlicks`. The rate is `settings.fps` (nominal: 24, 25, 30, 50, 60; default 30, today's value: 1,664 frames, 55.5 s) with `settings.ntsc` for the 1000/1001 fraction (24000/1001, 30000/1001); `planOf` takes it as a render setting. Resolution is `frame = floor(t x rate + 1/2)`, the **nearest frame, a half to the later one**, in integers (BigInt): **this keeps the rule of 0001 and 0002 (`Math.round`) and does not use `floor(t x fps)`**, because every frame lag measured for the reveal.js lifecycle (0002 as-built item 1) was measured under the nearest-frame rule and a floor would move frames by up to one; the lead named the floor as an example and left the rule to be written down. The renderer's lags are declared in frames at `lifecycle.measuredFps` (30) and are the same TIME at any rate. A core test shows the same IR at 24 and 60 fps resolves each anchor to the same time within one frame. There is **no per-beat container frame rate** (an MP4 has one rate); "animate on twos" is a sampling modifier on a curve or element, spec 0005. The encoder and the capture support `ntsc = false` at the rates their lifecycle was measured at; `ntsc` is refused by them until built.
- **2026-10-29, the JSON Schema is generated; each construct says where it came from.** The Effect Schema in `core` is the only hand-written definition. Each construct of the IR carries Schema annotations `origin` (for example `SMIL 3.0 timing, endsync`; `Harel 1987, depth`; `Fran untilB`) and, where reebeat's meaning differs, `deviation`; the generated document renders them. The construct catalogue is spec 0007.

- **2026-10-29, three clocks (operator-approved).** Time is kept in three kinds that meet only at the end: **logical** time is the order of events (which State follows which; what the machines say, with no number), **media** time is exact seconds (whole flicks, the IR's unit; audio in exact samples, 48 kHz in the speech cache and the mix), and **frame** time is the output frame at `settings.fps`, a render setting. Resolution goes logical, then media, then frame. 0004 builds the first and the last: the machines and the combinators are logical (an `all` or a `first` picks occurrences by order), the IR and the offsets are exact flicks, and the Timeline's frames are the nearest frame. What 0004 does **not** build is the middle step: resolution still adds rounded frames, one rounding per addend (see "25 fps is refused", below). Resolving in media time and rounding once at the end is the first work of 0005.
- **2026-10-29, two IRs, named apart (operator-approved).** The **story IR** is the declared graph (`GraphSchema`: States, Elements, Lines, Effects, the source: authored, canonical JSON, `version: 1`). - **2026-10-29, nearest frame; the tie rule.** An exact time becomes a frame by `floor(t x rate + 1/2)`: the nearest frame, and **a time exactly half way between two frames goes to the later one** (the half rounds up, also for a negative time: `-0.5` frames is frame 0). The lead's example said `floor`; the lifecycle lags of `capture-chromium` were measured with the nearest-frame rule and `floor` would move every measured frame by up to one, so the rule stays. `framesOfFlicks` is the only place that rounds (BigInt, so no float drift).
- **2026-10-29, 25 fps is refused (fail closed, operator-approved).** Rounding each addend on its own makes the same story land up to 1.5 frames away at 25 fps compared with 60 fps (`r1` of a test story: 4.16 s against 4.1 s; half-frame quantities such as 0.5 s = 12.5 frames and 0.3 s = 7.5 frames add up), while 24, 30, 50, 60 and the NTSC rates stay within one frame (`rates.test.ts`). 0004 does not offer a rate whose results it cannot stand behind: `fps` is one of 24, 30, 50, 60 (with `ntsc`), and 25 fails with a message that names spec 0005. 0005's first falsifier: every preset resolves to within one frame across rates once the rounding happens only at the end.

- **2026-10-29, SMIL notes from the catalogue spike.** SMIL 3.0 spells the `endsync` values `first`, `last`, `all` and `media`; the `all` combinator is the later of its operands, which is `endsync="last"` for a time container whose children each end once; `all(...)` here is named after RxJS's `forkJoin` and the table's `endsync="all"` is read as that. SMIL accepts an end equal to the begin; `until` here ignores an occurrence at or before the fire frame (strictly after), so a ring that would end the frame it begins is not zero long. SMIL keeps one current interval per element and restarts on a repeated begin event; instances here do not restart each other (decision 5).
- **2026-10-29, `all` is `last` (found by the spec 0007 catalogue spike, operator-ratified).** The combinator defined as the latest of the last occurrences of its operands is SMIL's `endsync="last"`; SMIL's `endsync="all"` is a different rule (every child has ended, counting repeats). The combinator is renamed **`last`** (`last(a, b)`; origin: `SMIL 3.0 timing, endsync="last"; RxJS forkJoin (explanatory only)`). Everywhere above that reads `all(...)` as a combinator now reads `last(...)`. `all` is no longer a reserved id; `last` is. The combinators of 0004 are `each`, `first`, `last` (plus `within`, offsets, `let`, `until`, `when`).
- **2026-10-29, the v1 adopt set of spec 0007 (operator-ratified; the table is "adopt set" in 0007, PR #11).** v1 is only what 0004 and 0005 need: syncbase anchors; `each`, `first`, `last`; `until`; explicit `restart` (`always`, `whenNotActive`, `never`, `overlap`; 0004 uses `overlap`); explicit `fill` (`remove`, `freeze`); statechart compound (the Scene), parallel (the Element's regions) and final; curves with `step`; exact time and the negative-begin cut-off rule (decided for 0005). **Later, not in the Schema:** `par`/`seq`/`excl` beyond what the statechart gives, internal and external transitions, eventless transitions, `done` events, `In()`, min/max, repeat, history, `count`, `snapshot`, time warp, integral. 0004 builds the first group as far as it applies to it: the three combinators, `until`, `restart` and `fill` declared as data (below); curves with `step` and the negative-begin rule are 0005.
- **2026-10-29, `restart` and `fill` are declared, per verb.** SMIL's `restart` and `fill` were implicit; each verb of the grammar now declares both as data in `grammar.ts` (`restartModes`: `always`, `whenNotActive`, `never`, `overlap`; `fillModes`: `remove`, `freeze`), and the grammar document prints them. Every verb declares `restart: overlap` (the instances of one effect are independent: a begin event that arrives while an instance runs starts another one, which is none of SMIL's three values, hence the fourth name) and the other three values are not authorable until a window-bearing effect repeats, so no verb may declare them (a test fails if one does). `fill`: `show` is `freeze` (it stays shown until the slide change), `focus` is `remove` (the ring is removed at its end, or at the slide change), `sound` is `remove`. They are per verb, not per effect, because a per-effect field would store a fact that the verb already determines. This records decision 5 as the named deviation.
- **2026-10-29, simultaneous events (found by the spike).** FRP's `merge` keeps two occurrences that happen together; the algebra here does not. **The occurrences of one event at the same frame are one occurrence** (a begin-value list with two equal times begins once; an effect fires once per moment): `each(a, b)` with `a` and `b` at one frame is that frame once, with the window of the first operand; `last` and `first` ties give the frame once; a `sound` there sounds once. **Two different effects at one frame both fire**, in declaration order, in one Beat. **`until` at an equal frame** is ignored: the end of an instance is the first occurrence strictly after its fire frame (SMIL accepts an end equal to the begin; a ring that began and ended in one frame would show nothing, so the rule differs on purpose); an occurrence before the fire frame is ignored the same way. Each case has a marble fixture and a mutant that keeps both occurrences.
- **2026-10-29, the IR stores no derived fact (found by the spike; JSON may become the source in 0006).** (1) `Id` is built from `idPattern`, the one definition of an id (the JSON Schema gets its `pattern`); (2) a chapter's scene ids are derived from the scenes' `chapterId`, not stored twice; (3) a Line's `words` are derived from its text (the times come from the alignment, which is not IR), so the story IR keeps only the text; (4) the text of an expression (`written`) is not stored next to the expression: `plan --timing` prints the canonical form (`when(one.move.progress >= 50%)` for what was written `one.move.50%`), and the sugar is read, never stored.
